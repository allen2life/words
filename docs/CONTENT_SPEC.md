# 题库内容生成规范（供内容生成 Agent 严格遵守）

本项目是国风每日解谜游戏，**内容即产品**。题目文化考据出错会被玩家放大传播，
因此下列规则为硬性约束，任何一条不满足即视为不合格。

---

## 一、《诗藏》条目规范

### 1.1 结构

```ts
{
  id: 'sz-033',                      // 递增，不复用
  title: '静夜思',                    // 诗题，不含书名号
  dynasty: '唐',                      // 唐/宋/先秦/汉/魏晋/南北朝/元/明/清
  author: '李白',                     // 无名氏写"无名氏"
  fullPoem: ['床前明月光', '疑是地上霜', '举头望明月', '低头思故乡'],  // 逐句，不含标点
  targetLine: '举头望明月',            // 必须是 fullPoem 中某句，或该句的连续子串
  targetIndex: 2,                     // targetChar 在 targetLine 中的 0 基下标
  targetChar: '明',                    // 单字
  tier: 'yellow',                     // yellow|green|blue|purple
  clues: {
    tone: '平声 (阳平 · 舒展悠长)',      // 平仄归属 + 感受
    radical: '日 (日部 · 与光明相涉)',   // 部首 + 与字义的关联
    imagery: '……'                       // 修辞/画面，一句话
  },
  appreciation: '……',                 // ≥40 字，讲清"为什么这个字好"，最好引诗话/典故
  authorBio: '……'                     // ≥20 字，生卒年 + 字号 + 一句评价
}
```

### 1.2 硬性校验（脚本会自动检查，不满足直接失败）

| 规则 | 说明 |
|---|---|
| `targetLine[targetIndex] === targetChar` | **最容易错**，务必用代码算下标，不要手数 |
| `targetLine` 必须被 `fullPoem` 某句包含 | 可为整句，也可为长句的前半 |
| `fullPoem` 每句不得含空格 | 去掉所有标点 |
| `clues` 三项均非空 | tone / radical / imagery |
| `appreciation` ≥ 20 字 | 建议 60–150 字 |
| `authorBio` ≥ 10 字 | 建议 30–80 字 |
| `id` 唯一 | |
| `targetChar` 不得与既有条目重复出题句 | 同一句不重复出题 |

### 1.3 内容质量要求（人工标准）

1. **必须是"炼字"题**：目标字要是该句最见功力的一字，不能随便挑一个字。
   优先选有诗话/笔记记载的炼字（如王安石"绿"、贾岛"推敲"、宋祁"闹"）。
2. **不得改写原文**：`fullPoem` 必须与通行版本一致，异文需在 `appreciation` 中说明。
3. **`targetChar` 尽量在 `targetLine` 中只出现一次**，若重复必须在 `appreciation` 说明。
4. **难度分层比例**：yellow 约 25%、green 约 40%、blue 约 25%、purple 约 10%。
   - yellow 蒙学入门：小学必背
   - green 诗文通识：中学古诗文
   - blue 古文学高阶：高中及大学拓展
   - purple 文脉宗师：楚辞/汉赋/冷门千古句
5. **同一首诗只出一道题**；同一作者可多次，但不要连续堆叠。
6. **朝代分布**：唐诗约 45%、宋诗/词约 30%、先秦汉魏约 10%、元明清约 15%。

## 二、《文脉》条目规范

### 2.1 结构

```ts
{
  id: 'wm-023',
  dateStr: '2026-09-28',            // 仅作存档展示；实际出题按 dayIndex 取模
  title: '第 271 期 · 某篇',         // 期号连续递增
  groups: [                          // 必须恰好 4 组
    {
      id: 'wm-023-g1',
      theme: '……',                   // 该组共同主题，10–20 字
      dimension: '同意象寄托',         // 分类维度
      tier: 'yellow',
      tierName: '蒙学入门',
      words: ['A', 'B', 'C', 'D'],    // 恰好 4 个词
      exegesis: '……'                  // ≥60 字，讲清四者为何同类，最好引出处
    },
    // g2/g3/g4 同理
  ]
}
```

### 2.2 硬性校验

| 规则 | 说明 |
|---|---|
| 每组恰好 4 个词 | |
| 每期恰好 4 组 | |
| 全期 16 个词**互不重复** | 跨组重复会让谜题无解 |
| 同一期四组 `tier` 覆盖四阶 | 建议 yellow/green/blue/purple 各一 |
| `exegesis` ≥ 30 字 | 建议 80–160 字 |
| 词组之间**不能有跨组歧义** | 例如"李白"不能既属"唐代诗人"又属"诗仙" |

### 2.3 内容质量要求

1. **每组必须"恰好四个"**，不能有第五个明显也属于该组的词混在其他组里。
2. **四个词地位对等**：不能三个是朝代名、一个是人名。
3. **避免生僻到无人认识的词**，也避免过于浅白（如"苹果/香蕉"）。
4. **`dimension` 常用值**：同意象寄托 / 同哲学思想 / 同文体体例 / 同器物名 /
   同流派作家 / 同典籍名 / 同时序称名 / 同工艺名 / 同礼制名 / 同典故出处。
5. **同一主题不要连续多期重复**（如连续三期都是"四大发明"）。
6. **每期建议设定一个统一"篇名"**（如"草木篇""舟车篇"），使四组有整体感，
   但不强制四组属于同一大类。

## 三、输出格式要求

- 只输出一个 TypeScript 文件内容，形如：

```ts
import type { ShizangPuzzle } from '../../types/game';

export const SHIZANG_002: ShizangPuzzle[] = [
  { ... },
  { ... },
];
```

（《文脉》对应 `WenmaiPuzzle` / `WENMAI_002`）

- **不要**输出解释、不要 Markdown 代码围栏之外的说明文字。
- 字符串统一用单引号；中文引号用「」或“”，避免与 JS 引号冲突。
- 每个对象后加逗号。

## 四、自检清单（提交前必须逐条确认）

- [ ] 每个 `targetIndex` 都用代码验证过 `targetLine[i] === targetChar`
- [ ] 没有重复 id、没有重复出题句
- [ ] 所有 `clues` 三项齐全
- [ ] `appreciation` / `exegesis` 达到最低字数
- [ ] 诗句原文无错字、无标点、无空格
- [ ] 难度比例接近约定值
- [ ] 文件能被 `npx tsc -b` 编译通过
